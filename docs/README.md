# docs — 문서 지도

어디서 무엇을 보나. 코드·문서가 다르면 **`contracts/` > `docs/plan.md` > `docs/requirements.md`** 순(루트 CLAUDE.md 0).

| 파일·폴더 | 내용 | 언제 보나 | 소유 |
|---|---|---|---|
| `mvp-checklist.md` | 금요일 [필수]만 뽑은 2~3쪽 요약 | **매 작업 전 먼저** | 연동·인프라 담당 |
| `work-order.md` | 요구사항정의서 전 항목을 작업 T01~T105로 묶은 전체 작업 순서·6명 레인 배치·결정 기한. 노션 작업 현황표의 원본 | 오늘 내 순서, 선행 작업, 완료 판정 위치 | DB·메일 담당 |
| `plan.md` | 기획서 v1.3 (설계·일정·역할 원본, **동결**) | 설계 근거를 찾을 때(2-4 등급, 3장 아키텍처, 5장 데이터, 6장 안전, 7장 계약, 9~11장 일정·역할·운영) | DB·메일 담당 |
| `requirements.md` | 요구사항정의서 v1.3 (**동결**) | 수용 기준(G/W/T)으로 완료를 판정할 때 | DB·메일 담당 |
| `review-v1.3.md` | v1.3 검토 의견 — 무엇이 왜 바뀌었나 | 결정 이유가 궁금할 때 | 연동·인프라 담당 |
| `ui-backlog.md` | 자잘한 UI 수정 모음(바로 고치지 않음) | 화면에서 거슬리는 것이 보일 때 | 화면 담당 |
| `night/` | 야간 작업 루프 지시문(`PROMPT.md`)·파트별 큐(`PLAN-*.md`)·로그(`LOG-*.md`) | 퇴근 전 큐 정리, 아침 LOG 확인 | 연동·인프라 담당(총괄), 각 파트 |
| `handoff/` | 로테이션 인수인계 메모 `<MMDD>-<컴포넌트>.md` | 로테이션마다 | 인계자 |
| `demo/` | 시연 시나리오·체크리스트·리허설 측정 기록 | 10/15 D-1부터 | 팀장(부 화면 담당) |
| `decisions/` | 결정 기록 `NNN-제목.md`(결정·이유·대안 3줄) | 결정이 날 때마다 | 결정자 |
| `zabbix/` | Zabbix 조사 결과·버전 캡처·권한 시험·접속 주소·API 정리 | 실연동 전환 때 | Zabbix·MCP 담당·팀장 |
| `frontend/`, `backend/` | 영역별 설계 메모(필요할 때만) | — | 각 파트 |

- 기획 원본(구글 드라이브 통합 기획서, 노션 공유문서)은 저장소에 없다. 제품 정체성·차별점은 `plan.md` 1-3.
- 노션은 **사람이 갱신**한다(3줄 보고·진행 현황·작업 현황표). Claude Code는 읽기만.
