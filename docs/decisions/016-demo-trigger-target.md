# 016 데모 트리거 목표 시간 — 120초로 현실화 (T59, NFR-PERF-006)
- 결정: 데모 템플릿의 트리거 식·임계값(`avg(...,1m)>85`, High)과 `system.cpu.util` 30초 수집은 **그대로 둔다**. 데모 목표 "주입 → High 장애"를 **90초 → 120초 이내**로 고친다(팀 서버 실측 104초, Issue #60). 남는 시간은 대본의 대기 설명(구조도·안전 3원칙, 약 2분)으로 흡수하고, 주입은 `-Minutes 3`으로 한다(5분 이상이면 원본 Warning 트리거가 같이 떠 장애가 2건이 된다).
- 이유: 같은 데모 템플릿이 팀 PC 6대에 연결돼 있어 임계값을 낮추거나(75~80%) 식을 줄이면(`avg(...,#1)`) 평소 부하에서도 High가 뜨고, Agent가 심각도 2 이상을 자동 분석하므로 데모 화면에 잡음 장애가 생긴다. 14초 차이는 데모 합격선(3분 이내, `docs/demo/README.md` 리허설)을 깨지 않는다. 데모 당일(10/16) 트리거를 바꾸면 운영 Zabbix 재적용과 재측정이 필요해 위험이 더 크다.
- 대안(기각): ① 임계값 75~80% 하향 ② 식 `avg(...,#1)`로 단축 ③ 수집 주기 15초 — 모두 오탐·재적용·재측정 부담. 리허설에서 120초를 넘기면 ①을 데모 호스트에만 적용하는 것을 다시 검토한다.
