# demo — 시연 시나리오·체크리스트·리허설 기록 (기획서 11-5, 담당 팀장 · 부 화면 담당)

## 시나리오
1. **D-MAIN — CPU 과부하**: 데모 PC에 `infra/scripts/inject-cpu.ps1 -Minutes 5` → 1분 트리거(High) → 현황 홈에 새 장애 → 장애 상세: 리포트(원인 후보 TOP3, 근거 패널 클릭으로 어떤 도구를 언제 호출했는지) → 변경 계획 미리보기(A·B·C 배지, B 단계의 사전 확인·예상 효과·위험·**롤백**을 읽어 줌, **실행 버튼 없음** 강조) → 메일 도착 화면. 대사: "승인자는 명령어 한 줄이 아니라 되돌리는 방법까지 같이 봅니다. 그리고 이 화면에는 실행 버튼이 없습니다."
2. **D-UNKNOWN — '확인할 수 없음'**: AI 어시스턴트에 "이 서버 백업 작업이 원인인가?" → 수집하지 않은 정보라 "확인할 수 없음 · NOT_COLLECTED"(지어내지 않음).
3. 제안 장면(채택 `(TODO: 추후결정 — 결정자 팀장, AS-B11)`): **D-BLOCK** C 빨강 배지 "금지 · 사람이 판단" — "AI가 '안전'이라고 적어도 규칙 파일이 '금지'로 바꿉니다. 실행 여부는 LLM이 결정하지 않습니다." (fallback 모드에서 보이려면 FR-AG-026) / **D-ENGINE** 대기 2분 동안 `packs/it/` 구조·엔진 분리 설명 / **D-NUMBERS** 마무리에 "잘못 통과 0/N, 과잉 차단 M/N" + 리허설 실측 시간.
4. 예비 — 디스크 부족([선택]): 시간 남으면 `inject-disk.ps1`.

**발표 문구 검수**(DB·메일 담당·화면 담당): "기존 서비스는 원인을 검증하지 않는다", "기존은 수동/자동 이분법", 금요일 기능을 넘는 "영향을 계산한다·안전성을 실측했다"(현재형)는 쓰지 않는다.
