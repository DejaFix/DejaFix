# 06. 시연 흐름·UI 문구 (발표 자료 기준)

출처: MVP 발표 자료(2026-10-20, 팀 DejaSix, 14쪽)와 `docs/demo/`. 앞 문서가 "무엇이 있나"라면 이 문서는 **"화면이 어떤 순서로, 어떤 말로 보였나"** 를 남긴다.

## 1. 원본 프로젝트에서 프론트의 위치

- 제품: **장애 대응 코파일럿 · Zabbix AI** — "AI가 분석 · 규칙이 실행 통제 · 사람이 최종 결정".
- 요청은 한 방향: `화면(Frontend) → Backend → AI Agent → Zabbix MCP → 운영 Zabbix`. 역방향 호출 경로가 없다.
- 프론트가 아는 것은 **Backend의 `/api` 하나**뿐이다. Agent·MCP·Zabbix를 직접 부르지 않는다.
- Docker Compose 서비스 5개(Frontend, Backend, AI Agent, Zabbix MCP, Scheduler), **외부 공개 포트는 8080 하나**(프론트 nginx).
- 프론트가 직접 쓰는 데이터는 없다. JWT만 `sessionStorage`에 둔다.
- 세 원칙(발표 3쪽): ① 운영 Zabbix는 조회만 ② 조치는 미리보기까지 ③ 근거 없으면 "확인할 수 없음"(값을 지어내지 않고 **사유와 시각**을 표시).

## 2. 시연 5단계 ↔ 화면

| 단계 | 발표에서 말하는 것 | 화면·컴포넌트 | 데이터 | 확인할 것 |
|---|---|---|---|---|
| 1 | 서버에 CPU 부하 발생 | (화면 없음) | — | — |
| 2 | 약 2분 뒤 High 알람 → 현황에 새 장애 | `Dashboard` 장애 목록, 헤더 `UrgentBanner`, 사이드바 배지·`SystemList` | `useIncidents` (15초 폴링) | 15초 안에 맨 위에 새 장애, "새 장애" 칩 |
| 3 | 장애 상세: 원인 후보 3개 · 영향 범위 · 근거 ID | `IncidentSummary`(`FocusCard`) + `IncidentDetail`: 원인 카드, `ConfidenceChip`, `EvidenceIds`·`EvidencePanel` | `useIncidentDetail` | 확신도가 문자, 근거 칩을 누르면 도구 호출(인자·결과·시각)이 펼쳐짐 |
| 4 | 변경 계획은 미리보기만 · 담당자 메일 | `PlanStepCard`·`TierBadge`, `MailLogRow` | 같은 상세 응답 | **실행 버튼 없음**, B 단계의 사전 확인·위험·롤백, 메일 sent/failed |
| 5 | AI 어시스턴트: "확인할 수 없음" → 추정 · 확인 방법 | `AssistantPanel` + 확인 불가 칩 | `streamChat` (`POST /api/chat`) | 질문 "이 서버 백업 작업이 원인인가?" → 칩 `확인할 수 없음 · 백업 작업 여부 · NOT_COLLECTED` |

5단계의 답변 문장(추정·확인 방법 포함)은 **Agent가 만든 `final.content`를 그대로** 보여 준다. 화면이 문장을 만들지 않는다.
시연 대사(원본 `docs/demo`): "승인자는 명령어 한 줄이 아니라 되돌리는 방법까지 같이 봅니다. 그리고 이 화면에는 실행 버튼이 없습니다."

## 3. UI 문구 사전 (코드에 있는 그대로)

| 상황 | 문구 | 위치 |
|---|---|---|
| 값 없음 | `확인할 수 없음 · {사유 코드} · 수집 시각 MM-DD HH:mm`(KST, 시각이 없으면 생략) | `IncidentParts.Unknown` |
| 사유 코드 | `NO_DATA` · `STALE` · `TOOL_ERROR` · `NO_PERMISSION` · `NOT_COLLECTED` | 서버 계약 |
| 분석 상태 | 분석 완료 / 규칙 기반 리포트 / 분석 대기 / 분석 중 / 분석 건너뜀 / 분석 실패 | `AnalysisBadge` |
| 확신도 | 확신도 낮음 / 보통 / 높음 | `ConfidenceChip` |
| 조치 등급 | `A · 조회 · 안전` / `B · 변경 · 승인 필요(미구현)` / `C · 금지 · 사람이 판단` | `TierBadge` |
| 메일 | 발송됨 / 실패 / 건너뜀 (+ "시도 N회") | `MailLogRow` |
| 연결 | 정상 / 대기 / 끊김, "연결 상태 확인할 수 없음" | `ConnectionStatus`·`SystemList` |
| Zabbix 끊김 배너 | "Zabbix 연결이 끊겼습니다. 실시간 값은 확인할 수 없고, 저장된 장애와 리포트만 볼 수 있습니다." | `ZabbixBanner` |
| 헤더 배너 | "가장 급한 장애 · {심각도}(· 즉시 대응)" / "지금 급하게 확인할 장애는 없습니다" / "장애 현황을 확인할 수 없습니다" | `UrgentBanner` |
| AI 패널 | 부제 "조회 전용 · 변경은 계획까지만", 첫 말풍선 "운영 Zabbix 데이터를 조회해서 답합니다. 확인되지 않은 값은 추정하지 않고 '확인할 수 없음'으로 알려 드립니다." | `AssistantPanel` |
| AI 오류 | Agent 연결 안 됨 / 이 계정은 사용할 수 없음(operator 이상) / 서버에 연결할 수 없음 | `AssistantProvider` |
| 미구현 메뉴 | 메뉴에 "준비 중" 칩, 화면 "{이름} 화면은 준비 중입니다" | `Layout`·`ComingSoon` |
| 로그인 | "사내 계정으로 로그인" / "AI가 분석한 장애 원인과 대응 계획을 확인합니다." / "아이디 또는 비밀번호가 틀렸습니다" | `Login` |

문체는 "~합니다/~없습니다". 사유 코드는 영문 대문자 그대로 보인다(한글 풀이 툴팁은 아직 없음 — 개선 후보).

## 4. 이후 단계로 예정된 화면 (지금은 없음)

| 화면 | 근거 | 규칙 |
|---|---|---|
| **지식 카드** "비슷한 과거 장애와 당시 조치" (FR-RAG-009) | 발표 4~6·8쪽의 지식 검색 MCP, 결정 017. `[이후]` | 검색 결과는 **근거일 뿐**, 조치 등급은 규칙이 정한다. 관련 지식이 없으면 "확인할 수 없음". 청크 ID를 근거로 보여 준다 |
| **해결 메모 입력** (FR-RAG-010) | 결정 017(작성은 Backend API, 화면은 Issue로 요청) | Zabbix에 쓰는 화면이 아니라 사람이 적는 메모. 04 문서의 "쓰기 버튼 금지"와 범위가 다르니 도입 전에 결정을 남긴다 |
| **승인·위임 흐름 화면** | 발표 11~12쪽(A2A 단계) | Task가 "입력 필요"에서 멈추고 B 이상은 사람이 승인. **이때 처음 승인 UI가 생긴다.** MVP에는 없다 |

## 5. 발표 자료용 화면 캡처 체크리스트

발표 2쪽 왼쪽 이미지는 지금 **실제 화면이 아닌 자리표시 카드**다. 아래 4장으로 바꾸면 "보여 주는 것"이 분명해진다.

1. **현황 홈** — 새 장애 + 헤더 배너 + 사이드바 시스템 상태(연결 4개 정상)
2. **장애 상세** — 원인 후보 + 확신도 칩 + 근거 패널을 펼친 모습
3. **계획 미리보기** — A/B/C 배지와 B 단계의 사전 확인·롤백, "실행 버튼 없음"이 한눈에 보이게
4. **AI 패널** — "이 서버 백업 작업이 원인인가?" → `확인할 수 없음 · … · NOT_COLLECTED`

조건: 브라우저 확대 125%·1920×1080 / 라이트 모드(슬라이드 본문 배경과 맞춤) / 주소창·북마크·알림 가림 / **서버 IP·토큰·개인 메일 주소가 보이면 가린다** / 캡처 일시를 파일 이름에 남긴다.

## 6. 발표 문구 검수 (원본 `docs/demo` 규칙)

- 쓰지 않는다: "기존 서비스는 원인을 검증하지 않는다", "기존은 수동/자동 이분법", 현재 기능을 넘는 "영향을 계산한다·안전성을 실측했다"(현재형).
- 숫자는 **조건과 함께** 쓴다: 측정일·횟수·N(예: "잘못 통과 0/N"). 리허설 기록은 **직접 본 시각만** 적는다.
