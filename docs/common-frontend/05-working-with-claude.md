# 05. Claude Code로 프론트 작업하기

이 프로젝트에서 **효과가 있었던 방식**만 적는다. 목적은 "시키는 사람이 달라도 Claude가 같은 품질로 하게" 만드는 것이다.

## 1. 잘 된 것

| 방식 | 이유 |
|---|---|
| **폴더 `CLAUDE.md`에 소유 폴더·하지 않는 것·테스트 명령을 적는다** | 세션이 새로 열려도 같은 규칙으로 시작한다. 길게 쓰지 않는다(아래 템플릿) |
| **계약(API 문서)이 먼저, 화면 코드는 계약 타입 위에** | 백엔드와 어긋나면 코드로 우회하지 않고 "계약 변경 제안"으로 올린다 |
| **화면별로 PR을 나눈다(400줄 이하, 스택 PR 가능)** | 리뷰가 쉽고 충돌이 줄었다. 상세 → 목록 → 레이아웃 순으로 올렸다 |
| **머지 전 검사 3종 + 수동 점검표**(04 문서 6장) | "된 것 같다"를 막는다. 브라우저로 못 본 것은 PR 본문에 솔직히 적는다 |
| **Issue를 업무 요청 게시판으로** (`to-frontend`·`to-infra` 라벨, 결론 한 줄 → 이유 → 다음 행동) | 사람이 말을 전달하지 않아도 파트 간 요청이 간다. 합의가 안 되면 `needs-human` |
| **"하지 않는 것"을 명시**(새 화면·새 기능·범위 밖 화면 수정 금지) | Claude가 스스로 범위를 넓히는 것을 막는다 |
| **자잘한 UI 수정은 백로그 파일에 모은다** | 급한 일 중간에 화면을 손대지 않게 한다 |

## 2. 일을 시킬 때 넣을 것 (5요소)

1. **목표** — 한 문장, 사용자에게 보이는 결과
2. **범위** — 건드릴 파일·폴더, **건드리지 말 것**
3. **기준** — 따라야 할 문서(계약·CLAUDE.md·토큰 규칙)
4. **완료 기준** — 어떤 화면·응답이 나오면 끝인지(체크박스)
5. **검증 명령** — `npm run lint` · `npx tsc --noEmit` · `npm run build` + 브라우저에서 볼 것

막히면 2번 시도 후 멈추고 이유를 적게 한다("실패하면 `[BLOCKED]`"). 모르는 값은 지어내지 않게 한다.

## 3. 프롬프트 템플릿

**(a) 화면/컴포넌트 추가**
```
frontend/CLAUDE.md 와 docs(common-frontend)의 01·02·04 문서를 먼저 읽어 줘.
목표: <화면/컴포넌트>를 만든다. 데이터는 lib/queries.ts 의 <훅>을 쓴다.
범위: src/pages/<…>, src/components/<…> 만. lib/·state/·mocks/ 는 고치지 마(필요하면 이슈로 요청 문안만 써 줘).
기준: 색은 토큰만, 값이 없으면 Unknown, 상태 라벨은 Record 표로.
완료 기준: - [ ] <화면 동작> - [ ] 모든 null 이 Unknown - [ ] lint·tsc·build 통과 - [ ] 실행/Run/Execute 요소 없음
브라우저로 확인 못 한 것은 PR 본문에 "못 봤다"고 적어 줘.
```

**(b) 컴포넌트 문서화 (공용 템플릿 세션)**
```
src/components 의 각 컴포넌트를 읽고 docs/02-components.md 표 형식으로 정리해 줘.
각 항목: 파일, 역할, props(타입 그대로), 범용/도메인 구분, 가져갈 때 주의.
코드에 없는 내용은 쓰지 마. 확인 못 한 것은 "확인 안 함"으로 표시해.
너무 길게 쓰지 말고, 새 프로젝트에서 가져갈지 판단할 수 있는 정보만 남겨.
```

**(c) 새 프로젝트 부트스트랩**
```
common-frontend/snapshot/frontend 를 새 저장소의 frontend/ 로 복사하고 templates/CLAUDE.frontend.md 를 frontend/CLAUDE.md 로 만들어 줘.
1) 팔레트(tokens.css·theme.css)를 <브랜드 색>으로 바꾸고 2) Layout 의 nav 를 <메뉴>로 바꾸고 3) Legacy 타입·옛 목·Cost/ServerCompare 를 지워 줘.
npm ci → lint → tsc → build 결과를 보고해 줘. 새 기능은 만들지 마.
```

## 4. 가이드라인 문서 쓰는 요령 (너무 짧지도 길지도 않게)

- **남길 것**: 파일 위치, 이름, 입출력(props·API), 규칙과 이유, 가져갈 때 걸리는 점
- **뺄 것**: 코드 전체 복붙, 변경 이력, 당연한 React 설명
- 표 > 문장. 한 항목은 한 줄에 끝나게. 코드 조각은 "이 모양이 핵심"일 때만.
- 사실만 쓴다. 코드로 확인한 것과 추정한 것을 구분한다(추정은 "확인 안 함").

## 5. 자주 막히는 곳

- 컴포넌트 파일에 상수·훅을 같이 export → `react-refresh` 린트 실패 → `lib/`로 분리
- `import type` 누락(`verbatimModuleSyntax`) → 타입은 항상 `import type`
- 실제 서버 없이 `VITE_MSW=off`로 띄움 → 로그인 불가(백엔드·시드가 먼저)
- 코드 줄바꿈 CRLF 경고(Windows) → 저장소 `.gitattributes`로 LF 고정, 커밋 전 `prettier --write`
- 주석 줄과 설정 줄을 헷갈려 값을 주석에 넣음(환경 설정 파일) → 값은 `#` 없는 실제 줄에
